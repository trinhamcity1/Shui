# Shui — Build Prompts

Shui is being rebuilt from a single-subject civics tutor into a **general-purpose
educational short-video platform**: TikTok's interaction model applied to learning
instead of to idle scrolling. Videos *are* the lessons, every lesson ends in a quiz,
learners pick subjects deliberately, and an AI tutor tests retention through
conversation.

This folder holds one prompt per build phase. Hand them to a coding agent **in
order**. Each phase assumes every prior phase is merged and building.

## Phase order

| # | File | What it delivers |
|---|------|------------------|
| 0 | `phase-00-foundation.md` | Strip the dead lesson engine, go English-only, wire the Firebase SDK, get a clean build |
| 1 | `phase-01-backend.md` | Firestore data model, security rules, Cloud Functions, R2 upload pipeline, seed content |
| 2 | `phase-02-feed.md` | The vertical video feed + end-of-video quiz + playback behavior |
| 3 | `phase-03-discovery-social.md` | Categories, topic pages, auth, profile, progress, likes, comments |
| 4 | `phase-04-ai-tutor.md` | The AI button: grounded chat + proactive retention checks |
| 5 | `phase-05-creator-mode.md` | In-app creator/mod console: topics, uploads, quiz builder, publish controls |
| 6 | `phase-06-web-dashboard.md` | Browser dashboard for bulk authoring on a laptop |
| 7 | `phase-07-lessons-on-demand.md` | A learner types any topic and gets a personal video + quiz, generated via Shui-WG |

Phases 0–3 are the shippable core. Phase 4 is the differentiator. Phases 5–6 are
what make the app maintainable without touching code again. Phase 7 is the
shareholder-directed pivot from a purely curated feed to lessons on demand.

## Shared conventions — every phase must follow these

**Product principle.** Every feature must answer: *does this help someone learn, or
does it just keep them scrolling?* No infinite algorithmic firehose, no engagement
streak guilt, no autoplay past a quiz the learner hasn't engaged with. Retention
means *knowledge retention* first, session retention second. When the two conflict,
knowledge wins — that is the entire reason this app exists.

**Platform.** iOS 17+, SwiftUI, Swift 5.9+. Xcode project is generated by XcodeGen
from `project.yml` — never hand-edit `Shui.xcodeproj`; edit `project.yml` and run
`xcodegen generate`, then commit both.

**App identity.** Name `Shui`, bundle `com.shui.app`, portrait-only, iPhone-only.

**Language.** English only. The app has no localization layer and must not grow one
in these phases. Do not add Vietnamese strings, `.lproj` bundles, an `AppLanguage`
enum, a `LocalizationManager`, or paired `textEN`/`textVI` fields. Multi-language is
a deliberate post-launch decision; leaving the scaffolding in place invites
half-migrated content. Use plain Swift string literals or a single `Strings.swift`
namespace of `static let`s.

**Backend.** Firebase project `shui-prod`.
- **Auth**: Sign in with Apple + email/password (both already enabled). Anonymous
  auth for guest browsing, upgraded via account linking on sign-in.
- **Firestore**: all structured data — categories, topics, video metadata, quizzes,
  comments, progress, roles.
- **Cloud Functions** (TypeScript, 2nd gen): anything that needs a secret or must not
  be trusted to the client — R2 upload signing, counter maintenance, AI tutor proxy,
  role assignment.
- **No Firebase Storage.** Video lives in R2.

**Video storage.** Cloudflare R2, bucket `shui-videos`, public base
`https://pub-29f895ffbdcf49779204f67d1a69af9b.r2.dev`. Uploads go **direct from
client to R2** using a presigned URL minted by a Cloud Function. R2 access keys live
in Function secrets and never in the app, the repo, or Firestore.

**Architecture.** MVVM with a repository layer. Views never touch Firestore, R2, or
`URLSession` directly. Each repository is a protocol with a live implementation and
an in-memory fake used by tests and previews. One `@MainActor` ViewModel per screen.
Async/await throughout; no completion handlers, no Combine except where SwiftUI
requires `ObservableObject`.

**Offline and caching.** Enable Firestore local persistence. Video is streamed and
relies on `AVPlayer`'s own caching plus an explicit prefetch window; do not build a
custom on-disk video cache in these phases.

**Security posture.**
- User `role` is authoritative in **Firebase Auth custom claims**, mirrored to the
  user's Firestore doc for display only. Security rules read the claim, never the doc.
- Firestore rules deny by default. Every collection gets an explicit rule and a
  matching test in the emulator suite.
- Never commit: R2 keys, model API keys, service-account JSON, `.env` files.
  `GoogleService-Info.plist` is a public client config and may stay committed, but
  the Google Cloud API key **must** be restricted to the iOS bundle ID.

**Testing and verification.** This codebase was originally authored on Linux and had
never been compiled. Treat a green Xcode build as the minimum bar, not a formality.
Every phase ends with:
1. `xcodegen generate` succeeds and the project opens.
2. The app builds and launches on an iOS 17 simulator with no console errors.
3. `xcodebuild test -scheme Shui` passes.
4. Firestore rules tests pass against the emulator (`firebase emulators:exec`).
5. The phase's own acceptance criteria, checked by hand in the simulator.

Write unit tests for pure logic (grading, scheduling, feed ordering, validation) and
rules tests for every security invariant. Do not write UI snapshot tests.

**Definition of done for content.** No feature ships reading hardcoded content from
the app bundle. If a creator can't change it from the creator console or the
dashboard, it isn't finished.

**Commits.** Small, imperative subject lines, one logical change each. Do not squash
a whole phase into one commit.

## Where the repo stands today (read before Phase 0)

The current app is `Shui`: a Vietnamese-language USCIS civics tutor. Useful parts and
liabilities, so you don't rediscover them:

**Worth keeping (adapt, don't rewrite):**
- `SpacedRepetitionScheduler` — clean SM-2 implementation with tests. Becomes the
  review engine for *all* subjects.
- `QuizGrading.swift` — multiple-choice grading and distractor generation.
- `VideoPlaybackController` / `VideoPlayerLayerView` — chrome-less `AVPlayerLayer`
  playback, already the right shape for a feed.
- `Theme.swift` — the `shell` design tokens.
- `scripts/sources/official_2025_civics.json` — verbatim transcription of the current
  official USCIS test, 128 questions with accepted answers. This is the seed content.

**Dead weight and known problems (Phase 0 deletes or fixes all of it):**
- The whole procedural "whiteboard" lesson renderer (`SceneCanvasView`,
  `SceneElementViews`, `LessonScript` scene models, `FallbackLessonBuilder`).
- The entire daily-session flow — `HomeView`, `HomeViewModel`, `SessionFlowView`,
  `SessionViewModel`, `SessionPlanner`, `SessionSummaryView`, `LessonPlayerView`,
  `ChapterPickerView` — which is **already unreachable**: `RootTabView` never
  presents it.
- `README.md` describes a bundled-video, no-backend app. That stopped being true
  three commits ago.
- Bundled content JSON is the 2008 100-question civics test. The official test is now
  the 2025 128-question version, already transcribed in `scripts/sources/` and wired
  to nothing.
- `current_officials.json` ships placeholder strings that `ContentStore.resolvedAnswers`
  feeds straight into the quiz, so five questions currently show
  *"Update in Settings > Content Admin before release"* as the correct answer. There is
  no Content Admin screen. `CurrentOfficialsConfig.isStale` is computed and never read.
- ~10 MB of placeholder MP4s are bundled in the app *and* mirrored to R2;
  `resolvedVideoURL` prefers the R2 URL unconditionally, so the bundled copies are
  unreachable dead weight with no offline fallback.
- Simulated OAuth and simulated tier upgrades (`AccountSheets.swift`) — real auth
  replaces them.
- `RuleBasedTutorAI` keyword-matching "AI" — the real tutor replaces it.
- Leftover untracked `Histudy.xcodeproj/` from the rename.
- `GoogleService-Info.plist` for `shui-prod` is committed with an unrestricted API key.
